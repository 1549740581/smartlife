# 产品需求文档（PRD）

## 1. 背景

当前小区内部租赁信息通常散落在微信群、公告栏或个人私聊中，信息可信度、时效性和管理效率都较差。项目希望通过统一的信息发布和审核平台，降低信息获取成本，提升可信度。

## 2. 目标

首期版本实现一套可用的“访客浏览 - 登录发布 - 审核 - 展示”闭环，覆盖房屋、车位和闲置物品三类生活信息。

## 3. 用户角色

### 住户用户

- 未登录时以访客身份进入小程序
- 使用微信小程序模拟登录
- 发布房屋、车位或闲置物品信息
- 查看自己发布内容的审核状态
- 浏览已通过审核的信息
- 直接联系发布者

### 审核员用户

- 以指定用户 ID 进入个人中心
- 在个人中心看到“后台审核”入口
- 登录管理后台接口
- 查看待审核内容
- 审核通过或拒绝
- 对异常内容执行强制下架

## 4. 核心业务流程

### 4.1 住户发布租赁信息

1. 用户进入小程序后默认以访客身份浏览公开信息
2. 用户从个人中心点击“我要发布”
3. 如未登录，则跳转登录页完成模拟登录
4. 选择发布类型：房屋 / 车位 / 闲置物品
5. 填写标题、描述、价格、联系方式等字段
6. 上传图片
7. 提交后状态为 `PENDING`

验收标准：

- 访客无需登录即可浏览公开内容
- “我要发布”入口固定出现在个人中心
- 必填字段校验明确
- 提交成功后能看到待审核状态
- 未审核内容不得对其他用户公开

### 4.2 审核员审核

1. 指定审核员用户在个人中心看到“后台审核”菜单
2. 普通用户不展示该菜单
3. 审核员进入待审核列表
4. 进入详情页核对信息
5. 选择通过或拒绝
6. 拒绝时必须填写原因

验收标准：

- 后台审核入口仅对指定用户 ID 可见
- 待审核列表按提交时间倒序
- 拒绝原因可被发布者查看
- 审核操作保留操作者和时间

### 4.3 信息展示

1. 访客或普通用户浏览已审核通过的房屋、车位或闲置物品信息
2. 用户按类型或状态筛选
3. 用户查看详情并联系发布者

验收标准：

- 仅 `APPROVED` 状态可公开展示
- 详情页可直接触达联系方式
- 已下架或被拒绝信息不在公开列表展示

## 5. 功能清单

### 必做

- 访客态浏览能力
- 用户体系基础能力
- 微信模拟登录能力
- 生活信息发布与查询基础能力
- 审核状态流转
- 审核员入口控制
- 管理员登录和审核接口
- 基础日志和异常处理
- 本地 mock / seed 数据

### 可后置

- 消息通知
- 多图片排序
- 搜索和高级筛选
- 数据统计看板

## 6. 非功能需求

- 接口统一返回结构
- 所有时间字段统一时区和格式
- 核心流程可审计
- 首期优先可维护性，不做过度复杂架构

## 7. 数据与状态要求

### 租赁类型

- `HOUSE`
- `PARKING`
- `ITEM`

### 审核状态

- `PENDING`
- `APPROVED`
- `REJECTED`
- `OFFLINE`

## 8. 非目标范围

- 不做社交广场
- 不做推荐流
- 不做租约签署
- 不做支付担保

## 9. 待确认事项

- 微信真实登录接入的时间点
- 审核员用户 ID 是否需要改为后台可配置
- 是否需要独立管理后台前端
- 图片文件存储方案
- 审核入口是否需要更细粒度角色区分
