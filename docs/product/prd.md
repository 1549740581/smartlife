# 产品需求文档（PRD）

## 1. 背景

当前小区内部租赁信息通常散落在微信群、公告栏或个人私聊中，信息可信度、时效性和管理效率都较差。项目希望通过统一的信息发布、审核、沟通和订单流转平台，降低信息获取成本，提升可信度。

## 2. 目标

首期版本实现一套可用的“访客浏览 - 登录发布 - 发布审核 - 搜索筛选 - 站内沟通 - 订单确认 - 到期提醒”闭环，覆盖房屋、车位和闲置物品三类生活信息。

## 3. 用户角色

### 住户用户

- 未登录时以访客身份进入小程序
- 使用微信小程序模拟登录
- 通过底部一级菜单在“生活广场 / 个人中心”之间切换
- 发布房屋、车位或闲置物品信息
- 发布时通过多级联动选择地址
- 查看自己发布内容的审核状态
- 在个人中心进入租赁沟通列表
- 浏览已通过审核的信息
- 按关键词、类型和地址筛选公开信息
- 对看中的房源或车位发起站内租赁沟通
- 发送想租时间段卡片并等待房东确认
- 查看自己的承租订单、取消申请和到期提醒
- 直接联系发布者
- 对虚假或不实信息发起投诉
- 投诉时必须填写投诉理由，可上传图片或视频作为证据
- 查看自己的投诉记录和处理状态
- 收藏感兴趣的房源或车位信息
- 在个人中心查看"我的收藏"列表
- 对自己发布的已通过审核信息执行主动下架
- 对自己发布的已下架信息执行重新上架

### 审核员用户

- 以指定用户 ID 进入个人中心
- 在个人中心看到“后台审核”入口
- 登录管理后台接口
- 查看待审核内容
- 审核通过或拒绝
- 对异常内容执行强制下架
- 对异常出租订单执行管理员取消
- 查看和处理用户投诉
- 核实投诉后对虚假信息执行强制下架
- 对多次被投诉的房东发送警告
- 对投诉超过 2 次的房东执行账号锁定
- 对被锁定用户执行解锁操作

## 4. 核心业务流程

### 4.1 住户发布租赁信息

1. 用户进入小程序后默认以访客身份浏览公开信息
2. 小程序底部固定提供“生活广场”和“个人中心”两个一级菜单
3. 用户从个人中心点击“我要发布”
4. 发布页默认回填当前登录用户昵称为联系人
5. 发布页对标题、描述、价格、联系人、联系电话进行前端必填校验
6. 用户可选择发布类型：房屋 / 车位 / 闲置物品
7. 填写标题、描述、价格、联系方式等字段
8. 通过下拉多级联动选择发布地址
9. 当前城市固定为杭州，不允许修改；区县、街道和小区从后端地址表中读取
10. 上传图片
11. 提交后状态为 `PENDING`
12. 提交成功后返回个人中心查看发布状态

验收标准：

- 访客无需登录即可浏览公开内容
- 底部一级菜单固定为“生活广场 / 个人中心”
- “我要发布”入口固定出现在个人中心
- “租赁沟通”入口固定出现在个人中心
- 发布页必填字段校验明确，并在前端即时提示
- 发布地址必须来自后端地址数据
- 当前仅支持杭州地址，首条默认地址为 `杭州 / 滨江区 / 长河街道 / 卓悦华庭`
- 发布表单地址选择默认定位到首个可选地址
- 提交成功后能看到待审核状态
- 未审核内容不得对其他用户公开

### 4.2 审核员审核

1. 指定审核员用户在个人中心看到“后台审核”菜单
2. 普通用户不展示该菜单
3. 审核员进入待审核列表
4. 进入详情页核对信息
5. 选择通过或拒绝
6. 拒绝时必须填写原因
7. 发布者可在个人中心看到拒绝原因
8. 审核员登录后可查看出租订单列表并执行管理员取消

验收标准：

- 后台审核入口仅对指定用户 ID 可见
- 待审核列表按提交时间倒序
- 拒绝原因可被发布者查看
- 审核操作保留操作者和时间
- 审核工作台必须提供明确的拒绝原因输入入口，且不能为空
- 管理端必须提供订单列表和“管理员取消订单”操作

### 4.3 信息展示

1. 访客或普通用户浏览已审核通过的房屋、车位或闲置物品信息
2. 生活广场支持按关键词、类型、地址筛选
3. 地址筛选通过城市 / 区县 / 街道 / 小区多级联动完成
4. 用户查看详情并联系发布者

验收标准：

- 仅 `APPROVED` 状态可公开展示
- 详情页可直接触达联系方式
- 已下架或被拒绝信息不在公开列表展示
- 公开列表与个人中心的视觉和导航风格保持一致
- 搜索表单布局稳定，不允许出现明显挤压和遮挡
- 搜索表单地址选择默认定位到首个可选地址，输入框与选择器高度保持一致

### 4.4 租赁沟通与订单

1. 登录用户在公开详情页点击“我想租”进入沟通页
2. 当前版本不接真实微信互发消息，采用小程序站内消息模拟微信沟通
3. 租客可发送文字消息与房东沟通
4. 租客可发送租期卡片，填写开始日期和结束日期
5. 同一房源或车位在交叉时间段内只能有一个有效订单
6. 房东确认租期卡片后，订单状态变为 `ACTIVE`
7. 房源或车位状态同步变为 `RENTED`，并展示出租时间范围
8. 房东和租客都可以发起取消申请
9. 取消申请需要双方同意；双方同意后订单取消，房源重新进入公开展示
10. 到期前 15 天系统自动向双方发送到期提醒
11. 点击续约会产生新的订单
12. 超级管理员可以直接取消某个出租订单

验收标准：

- 沟通页至少支持文本消息和租期卡片两类消息
- 个人中心必须能进入沟通列表，并查看自己作为房东或租客参与的会话
- 房东确认后房源状态必须切换为 `RENTED`
- 交叉时间段下单必须被拦截
- 已出租房源不再出现在公开广场
- 双方同意取消后房源重新公开展示
- 到期提醒必须对双方可见
- 续约生成的新订单与原订单分离存储
- 管理员取消后订单必须变为 `CANCELED`，并同步释放房源公开状态
- 已锁定用户或房东被锁定时，不允许发起续租申请
- 房源已下架时，不允许发起续租申请

### 4.5 投诉与处罚

1. 用户发现虚假或不实信息时，可在详情页或个人中心发起投诉
2. 投诉时必须填写投诉理由，可选上传图片或视频证据
3. 同一用户对同一信息只能投诉一次
4. 用户可在个人中心查看自己的投诉记录和处理状态
5. 管理员在后台查看待处理投诉列表
6. 管理员核实投诉后，可选择接受或驳回
7. 接受投诉时，被投诉信息自动强制下架
8. 接受投诉时，被投诉房东警告次数 +1
9. 当房东警告次数达到 2 次时，系统自动锁定该房东账号
10. 账号锁定后，该房东名下所有已发布信息自动下架
11. 被锁定账号不能再发布任何新信息
12. 已出租的房源在房东被锁定后，不能再进行续租申请
13. 管理员可解锁被锁定的用户账号（解锁后警告次数不清零，再次被投诉核实将立即封号）
14. 解锁后用户恢复正常使用

验收标准：

- 投诉入口对登录用户可见
- 投诉理由为必填项
- 证据文件支持图片和视频格式
- 同一用户对同一信息重复投诉时必须拦截
- 投诉记录列表按创建时间倒序
- 管理员处理投诉时必须记录处理人和处理时间
- 投诉被接受后，被投诉信息状态必须变为 `OFFLINE`
- 警告次数达到 2 次时，用户状态必须变为 `LOCKED`
- 被锁定用户名下所有 `APPROVED` 状态信息必须变为 `OFFLINE`
- 被锁定用户不能发起续租申请
- 管理员解锁后，用户状态恢复为 `ACTIVE`，警告次数归零

### 4.6 收藏功能

1. 登录用户浏览房源详情时，可点击右上角收藏按钮收藏该信息
2. 已收藏的信息再次点击可取消收藏
3. 用户在个人中心可进入"我的收藏"列表
4. 收藏列表按收藏时间倒序展示
5. 可在收藏列表中直接取消收藏
6. 点击收藏项可跳转到详情页
7. 首页浏览时，已收藏的信息在卡片右下角显示"★ 已收藏"角标

验收标准：

- 收藏按钮仅对登录用户可见，访客点击后引导登录
- 收藏/取消收藏操作即时生效，无需刷新页面
- 收藏列表为空时展示空状态提示
- 首页已收藏角标与详情页收藏状态保持一致
- 信息被下架或删除后，收藏列表中对应项不再展示

### 4.7 用户主动上/下架

1. 发布者可在个人中心"我的发布"列表中对已通过审核（APPROVED）的信息执行"下架"操作
2. 下架后信息状态变为 OFFLINE，不再出现在公开列表
3. 已下架的信息可由发布者执行"重新上架"操作
4. 重新上架后信息状态恢复为 APPROVED，重新出现在公开列表
5. 已下架的房屋或车位不允许发起续租申请
6. 闲置物品同样支持上/下架操作
7. RENTED 状态的信息不支持主动下架（需等待订单结束或取消）

验收标准：

- "下架"按钮仅对 APPROVED 状态的记录显示
- "重新上架"按钮仅对 OFFLINE 状态的记录显示
- 下架/上架操作需记录审计日志（操作人、时间、状态变更）
- 续租接口对 OFFLINE 状态的房源返回明确错误提示
- 上/下架操作仅限发布者本人，其他用户无权操作

### 4.8 本地演示数据

1. 默认种子数据至少包含一条 `APPROVED` 房屋、一条 `RENTED` 车位和一条 `APPROVED` 闲置物品
2. 默认种子数据至少包含一条待房东确认订单和一条生效中的出租订单
3. 默认种子数据至少包含对应的站内沟通消息、租期卡片和系统提醒

验收标准：

- 新数据库初始化后可以直接看到公开广场、个人中心、沟通列表和订单管理的演示数据
- 演示数据必须通过 Liquibase 自动落库，而不是依赖手工执行 SQL

## 5. 功能清单

### 必做

- 访客态浏览能力
- 用户体系基础能力
- 微信模拟登录能力
- 生活信息发布与查询基础能力
- 公开列表关键词搜索能力
- 地址表驱动的多级联动选择能力
- 审核状态流转
- 审核员入口控制
- 管理员登录和审核接口
- Redis 持久化管理员会话
- 站内租赁沟通消息
- 出租订单确认、取消、续约
- 到期前 15 天提醒
- 管理员订单取消
- 投诉举报能力
- 投诉处理与房东处罚机制
- 用户账号锁定与解锁
- 收藏功能（详情页收藏、我的收藏列表、首页已收藏角标）
- 用户主动上/下架功能
- 小程序双 Tab 导航与基础视觉规范
- 基础日志和异常处理
- 本地 mock / seed 数据
- Testcontainers 集成测试

### 可后置

- 消息通知
- 多图片排序
- 多城市地址联动
- 数据统计看板

## 6. 非功能需求

- 接口统一返回结构
- 所有时间字段统一时区和格式
- 核心流程可审计
- 首期优先可维护性，不做过度复杂架构
- 数据库字符集统一为 `utf8mb4`，校验规则统一为 `utf8mb4_general_ci`
- Java 服务启动时必须先执行 Liquibase

## 7. 数据与状态要求

### 租赁类型

- `HOUSE`
- `PARKING`
- `ITEM`

### 地址限制

- 地址数据维护在 MySQL `address_option` 表
- 后端提供只读地址树接口供小程序级联选择
- 当前只支持杭州
- 当前默认初始化一条地址：`杭州 / 滨江区 / 长河街道 / 卓悦华庭`

### 审核状态

- `PENDING`
- `APPROVED`
- `REJECTED`
- `OFFLINE`
- `RENTED`

### 出租订单状态

- `PENDING_CONFIRMATION`
- `ACTIVE`
- `CANCEL_PENDING`
- `CANCELED`
- `COMPLETED`

### 用户状态

- `ACTIVE`
- `INACTIVE`
- `LOCKED`

### 投诉状态

- `PENDING`
- `ACCEPTED`
- `REJECTED`

### 投诉处罚规则

- 警告阈值：2 次
- 达到阈值后自动锁定账号
- 锁定后需管理员手动解锁
- 解锁后警告次数清零

### 沟通与提醒限制

- 当前“微信沟通”能力以小程序站内消息实现，不直接对接真实微信客服或订阅消息
- 到期前 15 天提醒先以系统消息形式发送给房东和租客
- 默认演示数据由 Liquibase 增量脚本维护，重建数据库后可直接联调

## 8. 非目标范围

- 不做社交广场
- 不做推荐流
- 不做租约签署
- 不做支付担保

## 9. 待确认事项

- 微信真实登录接入的时间点
- 审核员用户 ID 是否需要改为后台可配置
- 是否需要独立管理后台前端
- 图片文件存储方案
- 审核入口是否需要更细粒度角色区分

## 10. 文档同步约束

- 以后每次代码改动都必须同步检查并更新本 PRD
- 如果实现与 PRD 不一致，必须优先修正文档或明确调整实现
- PRD 必须长期保持与当前可运行版本一致，不能滞后
