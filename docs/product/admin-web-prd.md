# Smart Life PC端管理后台 PRD

## 1. 概述

### 1.1 背景

目前小程序管理功能仅通过移动端入口操作，存在以下问题：

- 移动端操作效率低，难以处理复杂的批量操作
- 表格数据展示受限，不便进行数据分析
- 管理功能分散，缺少统一的运营视图
- 地址维护需要直接操作数据库

### 1.2 目标

构建一套PC端Web管理后台，提供：

- 统一的用户管理入口
- 信息发布的全生命周期管理
- 投诉处理与用户处罚
- 运营数据面板
- 地址信息维护
- 与小程序用户体系打通的微信扫码登录

## 2. 用户角色

### 2.1 超级管理员

- 拥有所有模块的完整权限
- 可管理其他管理员账号
- 可查看和导出所有数据

### 2.2 运营管理员

- 用户管理（查看、锁定、解锁）
- 信息审核与下架
- 投诉处理
- 地址维护
- 数据面板查看

## 3. 功能模块

### 3.1 登录认证

#### 3.1.1 微信扫码登录

1. 打开管理后台登录页，展示微信登录二维码
2. 管理员使用微信扫描二维码
3. 系统校验该微信用户是否具有管理员权限
4. 校验通过后自动登录，跳转到首页数据面板
5. 登录状态保持 8 小时，超时需重新登录

#### 3.1.2 权限校验

- 扫码用户必须在小程序中已注册
- 扫码用户必须被标记为管理员（`User` 需扩展管理员标识或关联 `Admin` 表）
- 非管理员扫码提示"无管理权限"

验收标准：

- 二维码有效期 5 分钟，过期自动刷新
- 登录成功后 Redis 存储会话，支持多设备登录
- 退出登录清除会话

#### 3.2.1 核心指标卡片

| 指标 | 说明 |

| 用户总数 | 小程序累计注册用户数 |
| 活跃用户 | 近 7 天有操作的用户数 |
| 信息总数 | 所有发布信息数量（含已删除） |
| 待审核 | 当前 PENDING 状态信息数量 |
| 已上架 | 当前 APPROVED 状态信息数量 |
| 已出租 | 当前 RENTED 状态信息数量 |
| 待处理投诉 | 当前 PENDING 状态投诉数量 |

#### 3.2.2 趋势图表

- 近 30 天新增用户趋势（折线图）
- 近 30 天新增信息趋势（折线图，按类型分组）
- 近 30 天投诉趋势（折线图）

#### 3.2.3 分布统计

- 信息类型分布（饼图：房屋/车位/闲置物品）
- 信息状态分布（饼图：各状态占比）
- 地区分布 TOP10（柱状图：按小区统计发布数量）

验收标准：

- 页面加载时自动请求数据，展示 loading 状态
- 数据刷新按钮支持手动刷新
- 图表支持下钻到对应列表页

### 3.3 用户管理

#### 3.3.1 用户列表

| 字段 | 说明 |
| --- | --- |
| 用户ID | 系统唯一标识 |
| 昵称 | 微信昵称 |
| 手机号 | 绑定手机 |
| 状态 | ACTIVE / LOCKED |
| 警告次数 | 累计警告次数 |
| 发布数 | 该用户发布的信息总数 |
| 注册时间 | 首次登录时间 |
| 操作 | 查看详情、锁定/解锁 |

#### 3.3.2 搜索筛选

- 关键词搜索：昵称、手机号
- 状态筛选：全部 / ACTIVE / LOCKED
- 注册时间范围

#### 3.3.3 用户详情

- 基本信息展示
- 该用户发布的所有信息列表
- 该用户的投诉记录
- 操作日志

#### 3.3.4 锁定/解锁

- 锁定用户：确认弹窗 → 执行锁定 → 用户名下 APPROVED 信息自动下架
- 解锁用户：确认弹窗 → 执行解锁 → 警告次数归零

验收标准：

- 分页展示，默认每页 20 条
- 支持按注册时间排序
- 锁定/解锁需二次确认
- 操作成功后刷新列表

### 3.4 信息管理

#### 3.4.1 信息列表

| 字段 | 说明 |
| --- | --- |
| ID | 信息唯一标识 |
| 标题 | 信息标题 |
| 类型 | 房屋 / 车位 / 闲置物品 |
| 状态 | PENDING / APPROVED / REJECTED / OFFLINE / RENTED |
| 价格 | 展示价格或"面议" |
| 发布人 | 关联用户昵称 |
| 发布时间 | 创建时间 |
| 操作 | 查看、审核、下架 |

#### 3.4.2 搜索筛选

- 关键词搜索：标题、描述
- 类型筛选：房屋 / 车位 / 闲置物品
- 状态筛选：PENDING / APPROVED / REJECTED / OFFLINE / RENTED
- 地区筛选：城市 / 区 / 街道 / 小区（级联选择）
- 发布时间范围

#### 3.4.3 信息详情

- 完整信息展示（含图片预览）
- 审核记录列表
- 关联订单列表（房屋/车位）
- 投诉记录

#### 3.4.4 审核操作

- 仅 PENDING 状态可审核
- 通过：状态变为 APPROVED
- 拒绝：必须填写拒绝理由，状态变为 REJECTED

#### 3.4.5 下架操作

- 仅 APPROVED 状态可下架
- 下架需填写下架原因
- 状态变为 OFFLINE

验收标准：

- 待审核列表默认排在最前
- 批量审核通过支持多选
- 图片支持放大预览
- 所有操作记录审计日志

### 3.5 投诉管理

#### 3.5.1 投诉列表

| 字段 | 说明 |
| --- | --- |
| 投诉ID | 唯一标识 |
| 被投诉信息 | 关联信息标题 |
| 投诉人 | 发起投诉的用户 |
| 被投诉人 | 信息发布者 |
| 投诉理由 | 用户填写的投诉内容 |
| 状态 | PENDING / ACCEPTED / REJECTED |
| 提交时间 | 投诉创建时间 |
| 操作 | 查看、处理 |

#### 3.5.2 搜索筛选

- 状态筛选：PENDING / ACCEPTED / REJECTED
- 提交时间范围

#### 3.5.3 投诉详情

- 投诉信息完整展示
- 证据文件（图片/视频）预览
- 被投诉信息详情跳转
- 被投诉人历史投诉记录

#### 3.5.4 投诉处理

- 接受投诉：
  - 被投诉信息状态变为 OFFLINE
  - 被投诉人警告次数 +1
  - 若警告次数达到 2 次，自动锁定用户
- 驳回投诉：
  - 必须填写驳回理由

验收标准：

- 待处理投诉高亮显示
- 处理后刷新列表
- 锁定用户时同步下架其所有 APPROVED 信息

### 3.6 地址管理

#### 3.6.1 地址列表

| 字段 | 说明 |
| --- | --- |
| ID | 唯一标识 |
| 城市 | 城市名称 |
| 区 | 区/县名称 |
| 街道 | 街道/镇名称 |
| 小区名称 | 小区/社区名称 |
| 创建时间 | 添加时间 |
| 操作 | 编辑、删除 |

#### 3.6.2 搜索筛选

- 关键词搜索：城市、区、街道、小区名称
- 城市筛选

#### 3.6.3 新增地址

- 城市（必填）
- 区（必填）
- 街道（必填）
- 小区名称（必填）
- 保存时校验唯一性

#### 3.6.4 编辑地址

- 仅可修改小区名称
- 城市、区、街道不可修改（避免影响已关联数据）

#### 3.6.5 删除地址

- 若该地址已被信息引用，禁止删除
- 删除前二次确认

验收标准：

- 支持批量导入（CSV 格式）
- 新增时自动去重
- 删除校验关联数据

## 4. 非功能需求

### 4.1 技术选型

- 前端框架：React + Ant Design Pro
- 状态管理：React Query / Zustand
- 图表库：ECharts
- 构建工具：Vite
- 后端复用现有 Spring Boot 服务，新增 Web 管理接口

### 4.2 安全要求

- 所有接口需校验管理员 Token
- 敏感操作记录审计日志
- 防止 XSS / CSRF 攻击
- 接口限流保护

### 4.3 性能要求

- 列表页首屏加载 < 2s
- 分页请求响应 < 500ms
- 数据面板统计查询 < 3s

### 4.4 兼容性

- 支持 Chrome / Edge / Firefox 最新版本
- 最小分辨率 1280x720

- `REJECTED` - 已驳回

- `RENTED` - 已出租

- `ACTIVE` - 正常
- `INACTIVE` - 未激活
- `LOCKED` - 已锁定

**Complaint.ComplaintStatus**
- `PENDING` - 待处理
- `ACCEPTED` - 已接受
- `REJECTED` - 已驳回
