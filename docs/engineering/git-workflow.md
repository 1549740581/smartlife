# 协作流程

当前目录尚未初始化为 Git 仓库时，本文件作为推荐协作方式；一旦接入 Git，应按本流程执行。

## 1. 分支建议

- `main`: 可发布主干
- `feature/*`: 新功能开发
- `fix/*`: 缺陷修复
- `docs/*`: 文档调整

## 2. 提交建议

- 一次提交只解决一个清晰问题
- 提交前确保相关测试通过
- 重大设计调整先改文档再改代码
- 任何会改变需求理解的提交，必须同时更新 `docs/product/prd.md`

## 3. Pull Request 检查点

- 需求范围是否清楚
- 是否有测试或说明为何无法补测试
- 是否更新相关文档
- `docs/product/prd.md` 是否仍与当前实现一致
- 是否引入新依赖或新模块

## 4. AI 协作建议

- 新任务开始前先确认目标文件和验收标准
- 需求变化先更新 `docs/product/` 和 `docs/tasks/`
- 技术约束变化先更新 `docs/engineering/` 或 ADR
